> တိုင်းချက် အရင်းအမြစ် — `assets/calib/ref_hype_2026.json` (၂၀၂၆-၀၉-၂၀)

## ၀ · အရေးကြီးဆုံး စည်းမျဉ်း (ဖျက်ခွင့် မရှိ)

1. **QC ဂိတ် မလျှော့ရ။** `cut_in_speech = 0` · `lufs` · `true_peak` · `gfx_share` ·

2. **စကားသံ အလယ်မှာ ဘယ်တော့မှ မဖြတ်ရ** (F2 = ၀ အာမခံ)။
3. **မှန်းဆ မလုပ်ရ။** ပြင်ပြီးတိုင်း တိုင်းပြီး ကိန်းနဲ့ တင်ပြရမည်။
4. ရှိပြီးသား စွမ်းရည်ကို **ချဲ့ရမည်** — အသစ် မတည်ဆောက်ရ (အောက်တွင် ဘယ်မှာ ရှိလဲ ပြထားသည်)။

## ၁ · ref2 → **Slide Heavy** — ဂရပ်ဖစ် ကြာရှည် ရပ်ခြင်း

### တိုင်းထားသော ပစ်မှတ်
| | တန်ဖိုး |
|---|---|
| စာသား ဖန်သားပြင်ပေါ် ရှိချိန် | **၈၂%** |
| ဂရပ်ဖစ် ဧရိယာ p75 / အများဆုံး | **၂၃.၅% / ၇၉.၆%** |
| နေရာ | အလယ် ၇၇% · အောက် ၁၀% · အပေါ် ၁၃% |
| တစ်ချိန်တည်း စာသား အကွက် (p90) | **၁** ← အထပ် **မလို** |
| ဖြတ်ချက် | ၇.၂/မိနစ် · shot အလယ် ၄.၇၀s |

### ပြဿနာ (ကိန်းနဲ့)
IKKI ရဲ့ ဂရပ်ဖစ် ကတ် တစ်ခု ~**၁.၉ စက္ကန့်** ကြာသည်။
`၀.၇၄ × ၅၅၅s ÷ ၁.၉s = ကတ် ၂၁၅ ခု` — **မရနိုင်**။

### ဆောင်ရွက်ရမည့် အလုပ်
p90 = ၁ ဖြစ်သဖြင့် **အထပ် မလိုပါ**။ လိုတာက **တစ်ခုကို ကြာရှည် ရပ်**ခြင်း။

1. `core/dress.py` — `hold` **ရှိပြီးသား** (line ~၃၈၈ · `tpad stop_duration`)။
   ယခု `hold` ကို **share ပစ်မှတ်ကနေ ပြန်တွက်**ခိုင်းရမည်:
   `hold_i = (target_share × dur) ÷ n` · တစ်ခုချင်း `[၁.၀ , card_max_s]` အတွင်း။
2. `worker/run.py` — slide အရှည် ချိန်ညှိချက် (`_wantn` · ချုံ့/ဆွဲတင် block)
   ကို ကတ်အတွက်ပါ သုံးအောင် ချဲ့ရမည်။ **ဘောင် အလယ်ကို ချိန်ရ** —
   အနားကို ချိန်လျှင် drift နဲ့ QC ကျသည် (၂၀၂၆-၀၉-၂၀ တကယ် ဖြစ်ခဲ့)။
3. `card_max_s` ကို recipe ကနေ ယူသည် (`ref-slides` မှာ ၁၇.၀ ထားပြီး)။
   QC ရဲ့ `card_len` ဂိတ်လည်း **တူညီသော တန်ဖိုး** သုံးရမည် — မတူလျှင် ကျမည်။
4. ဧရိယာ ကြီးမား (p75 ၂၃.၅%) လိုသဖြင့် **အလယ်/အပေါ် နေရာ** template များကို
   ရွေးရမည် — `_avoid_band()` (မျက်နှာဇုန်) ကို **မဖျက်ရ**။

### လက်ခံမည့် သတ်မှတ်ချက် (တိုင်းပြီး ပြရမည်)
- `gfx_share` ∈ **၀.၃၀–၀.၄၂** · ဗီဒီယို အရှည် ၅ မျိုး (၆၅s · ၁၄၀s · ၃၀၀s · ၅၅၅s · ၉၀၀s) မှာ **အားလုံး ဘောင်ထဲ**
- `card_len` အားလုံး `[၁.၀ , ၁၇.၀]s` အတွင်း
- မျက်နှာဇုန် ထပ်မှု **၀**
- QC PASS — render ၂ ခု အနည်းဆုံး

## ၂ · ref3 → **Fast Cut** — အသံ မဖြတ်ဘဲ မြင်ကွင်း ပြောင်းခြင်း

### တိုင်းထားသော ပစ်မှတ်
| | တန်ဖိုး |
|---|---|
| မြင်ကွင်း ပြောင်းမှု | **၂၇.၉/မိနစ်** (၇၈၃s မှာ **၃၆၄ ခု**) |
| shot အရှည် | အလယ် **၁.၂၇s** · p25 ၀.၄၇s · ၆၄% က ၂s အောက် |
| ၀.၄၅s ကျော် တိတ်ဆိတ်မှု | **၁၀ နေရာ ပဲ** |
| စာသား | ၄၆% · အပေါ် ၃၄% · အောက် ၁၄% |

### အဓိက တွေ့ရှိချက် — ဒါကို မှားရင် အလုပ် အလကား ဖြစ်မည်
```
မြင်ကွင်း ပြောင်းမှု ၃၆၄ ခု
တိတ်ဆိတ်မှုနဲ့ ကိုက်နိုင်တာ  ၁၀ ခု
⇒ ကျန် ~၃၅၄ ခုက **အသံ မဖြတ်ဘဲ မြင်ကွင်း ပြောင်းတာ**
```
⇒ **「ပိုမြန် ဖြတ်」 ဆိုတာ မဟုတ်ပါ။** IKKI က F2 = ၀ အာမခံသဖြင့် စကားထဲ
မဖြတ်နိုင်ပါ။ လိုတာက **အသံ ဆက်တိုက် ရှိနေစဉ် ရုပ် ပြောင်း**ခြင်း —
punch-in / reframe / B-roll ထည့်ခြင်း။

### ဆောင်ရွက်ရမည့် အလုပ်
1. `core/broll.py:284–287` မှာ **`zoompan` ရှိပြီးသား** — ဒါပေမယ့် B-roll
   အတွက်သာ။ ⇒ **ပင်မ ရုပ်ပေါ် သုံးအောင်** ချဲ့ရမည် (`core/spans.py` ရဲ့
   span render ဒါမှမဟုတ် သီးသန့် module)။
2. Framing ၃ မျိုး အလှည့်ကျ: **wide → punch-in (၁.၁၅×) → off-centre**။
   ပြောင်းချိန်ကို **စကားလုံး နယ်နိမိတ်** (ASR words) နဲ့ မကိုက်ဘဲ
   `measure.speech()` ရဲ့ band-energy dip တွေနဲ့ ကိုက်ရမည် — ASR အချိန်မှတ်
   ကြမ်းလွန်းသည် (၂၀၂၆-၀၉-၁၈ တိုင်းထားပြီး)။
3. **အသံ လုံးဝ မထိရ** — ရုပ် filter သာ။ span နယ်နိမိတ် မပြောင်းရ
   (ပြောင်းလျှင် F2 ပျက်မည်)。
4. စာတန်း safe zone နဲ့ မျက်နှာဇုန်ကို punch-in ပြီးမှ **ပြန်စစ်ရမည်** —
   ချဲ့လိုက်လျှင် စာလုံး ဘောင်ပြင် ထွက်နိုင်သည် (ZAE မှာ တကယ် ဖြစ်ခဲ့)。
5. ၄K → 2560 proxy ဖြစ်သဖြင့် punch-in ၁.၂၅× ကျော်လျှင် **အရည်အသွေး ကျမည်** —
   ကန့်သတ် ထားရမည်。

### လက်ခံမည့် သတ်မှတ်ချက် (တိုင်းပြီး ပြရမည်)
- `ffmpeg scene>0.06` နဲ့ တိုင်းလျှင် **၂၀–၃၀ ပြောင်းမှု/မိနစ်**
- shot အရှည် အလယ်တန်း **၁.၀–၂.၀s** · ၂s အောက် **၅၀%+**
- `cut_in_speech = 0` **မပျက်**
- စာတန်း ဘောင်ပြင် ထွက် **၀** (frame တိုင်း စစ်)
- punch-in အမြင့်ဆုံး ၁.၂၅×
- QC PASS — render ၂ ခု အနည်းဆုံး
